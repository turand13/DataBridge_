# Требования DataBridge

## 1. Назначение

Утилита для приведения данных из разных форматов (CSV, JSON, XML, Excel)
к единому виду: чтение → валидация → конвертация → отчёт. Без БД, интерфейс — CLI.

## 2. Функциональные требования

### 2.1. Чтение данных

| Формат | Требования |
|---|---|
| CSV | с заголовками и без, настраиваемый разделитель, UTF-8 (в т.ч. BOM) |
| JSON | массив объектов; битый JSON / не-массив → ошибка |
| XML | плоская структура: корень → записи → поля; вложенность → ошибка |
| Excel (.xlsx) | первый лист по умолчанию, имя листа настраивается |

Формат определяется по расширению.

### 2.2. Валидация

| Правило | Параметры |
|---|---|
| `required` | `true`/`false` |
| `type` | `integer`, `float`, `string`, `date`, `boolean` |
| `min`/`max` | числа или даты |
| `pattern` | regex (полное совпадение) |
| `unique` | уникальность в наборе; `None` не участвует |
| `min_length`/`max_length` | целые |

`None` = отсутствие значения (срабатывает `required`), `""` = значение.
Валидатор типы не приводит — только проверяет приводимость.

### 2.3. Конвертация

- Чтение из любого формата → запись в любой.
- Маппинг полей по словарю `mapping`.
- Трансформации: `upper`, `lower`, `trim`, `dict_replace`, `timestamp_to_date`
  (минимум по ТЗ — 3, реализовано 5).
- Некорректные записи → `errors.csv`.

Порядок: **Reader → Validator → Converter → Writer**.
Маппинг применяется после валидации — схема описывает входные имена.

### 2.4. Отчёт

Консольная сводка: всего / успешно / ошибок / первые 10 ошибок / пути файлов.
`errors.csv`: `row_index,<поля>,errors`.
`report.html`: статистика + таблица ошибок.

### 2.5. CLI

databridge convert input.csv --to json --config schema.yaml --output output.json
databridge validate input.json --config schema.yaml --report report.html
databridge stats input.csv

Коды возврата: `0` — успех, `1` — ошибка данных/конфига, `2` — argparse,
`3` — внутренняя ошибка.

## 3. Нефункциональные требования

- Python 3.10+, без БД.
- Понятные ошибки (`DataReadError`, `DataWriteError`, `ConfigError`).
- Тесты: unit + интеграционные (по факту больше минимума).
- Документация: README + DOCS + примеры «до/после».
- Модули: `readers/`, `writers/`, `validators/`, `converters/`, `reporters/`, `cli/`.

## 4. Ограничения MVP

- Данные в памяти.
- XML — плоская структура.
- JSON — массив объектов.
- Excel — только `.xlsx`.
